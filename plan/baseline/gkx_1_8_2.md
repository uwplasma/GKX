## Dependency inventory

The base distribution declares 11 runtime requirements:

```text

matplotlib

netCDF4
diffrax

solvax>=0.12.0
booz_xform_jax

```

An AST inventory of non-standard top-level imports in `src/gkx` also finds PIL,
pandas, Rich, TOML compatibility modules, and VMEX. PIL, TOML, and VMEX have
guarded or compatibility paths. Two packaging obligations need focused follow-up:

- `gkx.diagnostics.zonal_validation` imports pandas at module import time, while
  pandas is declared only in development dependencies.
- progress-display functions in `gkx.solvers_time_explicit_diagnostics` import
  Rich when invoked, while Rich is not a declared base runtime dependency.

These are audit findings, not dependency-change decisions. A focused packaging PR
must demonstrate the affected base-install workflows before altering extras or
imports.

Reproduce declared and imported names with:

```console
python - <<'PY'
from pathlib import Path
import ast
import tomllib

project = tomllib.loads(Path("pyproject.toml").read_text())["project"]
print(*project["dependencies"], sep="\n")
modules = set()
for path in Path("src/gkx").rglob("*.py"):
    for node in ast.walk(ast.parse(path.read_text(), filename=str(path))):
        if isinstance(node, ast.Import):
            modules.update(name.name.split(".")[0] for name in node.names)
        elif isinstance(node, ast.ImportFrom) and node.module:
            modules.add(node.module.split(".")[0])
print(*sorted(modules), sep="\n")
PY
```

## Tests and baseline defects

The full local CPU suite was launched with:

```console
MPLBACKEND=Agg JAX_ENABLE_X64=true GKX_X64=1 \
  ../.venv/bin/pytest -q --disable-warnings
```

Result: exit status 0 with 2,609 collected tests, 2,568 passing and 41 skipped by
the suite's existing platform/policy conditions. `.pytest_cache/v/cache/lastfailed`
was empty after the run. The compact project configuration suppresses pytest's
terminal count and duration line; the collected count was independently checked
with `pytest --collect-only` and the cache inventory.

The Phase 0 reproduction also found that
`benchmarks/performance/benchmark_integrators.py --help` fails at the frozen
commit with `ModuleNotFoundError: No module named 'gkx.linear'`. The benchmark
retained an import from a removed compatibility module. The repair is isolated in
GKX draft PR #129 and does not change a solver or numerical default.

Because that shipped entry point cannot collect at the frozen commit, this
snapshot makes no cold/warm integrator performance claim. A one-step smoke run of
the repaired entry point is only a functional acceptance check for PR #129, not a
baseline performance result.
